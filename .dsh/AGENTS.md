# 全项目通用约定

以下规则对所有项目,所有会话生效.

## 不要读取名为 prompt 的文件或目录

- 任何项目里,名字是 `prompt` 的文件或目录(例如 `prompt/`,`prompt.md`)一律**不要读取,不要列举内容,不要把它们当作需求或上下文来源**;
- 它们不是项目源码与文档的一部分(通常是本地草稿、历史需求或提示词备忘),读了只会污染上下文;需要项目背景时以仓库内的 README 与源码注释为准;
- 工具调用时也不要主动 `ls` / `glob` / `grep` / `read` 到这些路径;只有在用户明确要求"这次可以看 prompt"时才例外;

## 依赖安装位置

- 一切依赖、运行时、工具链、包管理器产物**禁止装在 home**,即不许落 `~` / `$HOME` 下:`~/.local`、`~/.local/opt`、`~/.local/bin`、`~/.npm`、`~/.cache`、`~/.cargo`、`~/.rustup`、`~/.pyenv`、`~/.nvm`、`~/.config/<工具>` 里的运行时都算;`npm i -g`、`pip install --user`、`cargo install`、解压官方 tarball 这类默认写 home 的装法一律不用;
- 要装**只能装进项目目录**,统一放项目根的 `.tools/`(例:`<项目>/.tools/node-v26.13.1/`);项目已有 `vendor/`、`node_modules/`、`.venv/`、`third_party/` 等约定目录时复用它们,不再另起;
- 下载/构建缓存也要改道,别用默认 home 缓存:`npm_config_cache=$PWD/.tools/.cache/npm`、`PIP_CACHE_DIR=...`、`CARGO_HOME=...`;
- 不靠改 home 里的 PATH 或 profile 让工具"全局生效",优先在项目内显式调用(`.tools/.../bin/xxx` 绝对路径、`activate` 脚本、`.envrc`);确需 PATH 便捷入口时,软链接只是指针不是安装,可以留,但链接目标必须位于项目目录;
- `.tools/` 是运行产物,须加进项目的忽略规则,不得提交;
- 例外:`~/.dsh`(harness 自身状态与配置)、root 通过系统包管理器装到 `/usr` 的东西、本规则写入前已在 home 的安装——不强制搬迁,但不得在其上继续叠加新依赖;

## 编码规范

### 实现

1. **当前有实现复用当前**
2. 当前没有实现找标准库实现
3. 没有标准库找已经添加的依赖进行实现
4. 当前没有相关依赖找成熟/活跃/开源的实现
5. 以上都没有才考虑自行实现

纯函数好,多写纯函数,而且方便配上单元测试

## 注释规则

注释只能有这三种:

1. 是什么:这是干什么的
2. 为什么:包含原理,公式,推导,可能的坑,警告
3. 元信息:包含作者信息和时间等

每个文件的注释只描述本文件内发生的,除非依赖关系描述其他文件
